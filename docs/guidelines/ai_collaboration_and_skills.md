# AI 协作规范

## 1. 开始任务前
- 先阅读本规范索引，并检查相关 feature、Gradle 配置、资源文件和测试现状。
- 优先用非破坏性命令理解当前工程，不基于聊天记录猜测实现。
- 若发现用户要求与当前代码冲突，先说明冲突和建议处理方式。

## 2. 改动原则
- 保持最小可行改动，避免顺手重构无关模块。
- 不复制参考项目的业务逻辑、平台实现或仓储细节，除非用户明确要求。
- 借鉴参考项目时应转译为 Android/Kotlin/Compose 的本地规范和实现方式。

## 3. 交付要求
- 输出需包含变更摘要、关键文件、验证结果和未完成风险。
- 如果命令因环境限制未能执行，说明原因、影响范围和替代验证。
- 沟通、注释和交付说明默认使用中文。

## 4. 安全边界
- 不修改用户未要求的配置、证书、密钥、签名文件和本地环境文件。
- 不执行破坏性命令，除非用户明确授权。
- 遇到用户已有改动时，必须在其基础上继续，不得擅自回滚。
