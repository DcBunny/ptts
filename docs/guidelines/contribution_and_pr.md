# 提交与 PR 规范

## 1. 提交前检查
- 必须执行：`./gradlew :app:assembleDebug`
- 必须执行：`./gradlew :app:testDebugUnitTest`
- 若有可用设备或模拟器，执行：`./gradlew :app:connectedDebugAndroidTest`
- 修改 UI 时，至少人工或截图检查主要屏幕在常见尺寸下不重叠、不截断。

## 2. 提交内容
- 一个提交应聚焦一个目标，避免混入无关格式化或 IDE 元数据。
- 新增公共约定、目录结构或协作规则时，同步更新 `docs/guidelines/`。
- 新增依赖时说明用途，并优先通过版本目录 `gradle/libs.versions.toml` 管理。

## 3. PR 描述
- 背景：说明为什么需要该改动。
- 变更：概述用户可见行为和主要技术调整。
- 验证：列出实际执行的 Gradle 命令和结果。
- 风险：说明未覆盖的设备、权限、平台能力或后续待接入事项。

## 4. Review 关注点
- UI 是否符合既定视觉与交互目标。
- 状态和业务逻辑是否在合适层级。
- 文案、无障碍和测试标识是否稳定。
- 是否引入了不必要的跨模块耦合或平台副作用。
